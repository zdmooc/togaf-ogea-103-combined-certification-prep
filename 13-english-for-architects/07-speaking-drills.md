# Speaking Drills for Architects

## 1. Règle

Le but n’est pas de parler vite. Le but est de parler avec une structure stable.

Utiliser :

```text
Point
→ Reason
→ Example
→ Consequence
```

## 2. Drill 30 secondes — définitions

Répondre sans notes :

1. What is enterprise architecture?
2. What is TOGAF?
3. What is the ADM?
4. What is a stakeholder concern?
5. What is a baseline architecture?
6. What is a target architecture?
7. What is a transition architecture?
8. What is architecture governance?
9. What is a compliance review?
10. What is a work package?

## 3. Drill 45 secondes — différences

1. Baseline vs Target
2. Preliminary vs Phase A
3. Phase B vs Phase C Application
4. Data vs Application Architecture
5. Phase D vs Phase E
6. Phase E vs Phase F
7. Phase F vs Phase G
8. Phase G vs Phase H
9. Deliverable vs Artifact
10. ABB vs SBB
11. View vs Viewpoint
12. Repository vs Continuum

## 4. Drill 60 secondes — décision

Répondre avec `I would... because...` :

- A vendor proposes a product before requirements are clear. What do you do?
- A delivery team wants an architecture exception. What do you do?
- Operations was not involved in the target architecture. What do you do?
- Security requirements arrive late. What do you do?
- The organization wants a big-bang migration. What do you challenge?
- Two applications provide the same capability. How do you analyze the situation?

## 5. Drill 90 secondes — architecture

Sujet :

> Explain the MayaBank target architecture.

Structure :

1. current problem;
2. target characteristics;
3. key decisions;
4. migration;
5. governance.

## 6. Drill 2 minutes — migration

> Explain how you would migrate a critical legacy payment platform to a cloud-native target.

Points attendus :

- business continuity;
- dependencies;
- transition architecture;
- observability;
- security;
- pilot;
- migration waves;
- rollback;
- decommissioning.

## 7. Drill 2 minutes — architecture review

> A team implemented a design that differs from the approved architecture. Explain what you would do.

Ne pas répondre seulement `I would reject it`.

Parler de :

- reason for deviation;
- impact analysis;
- requirements;
- compliance;
- risk;
- exception process;
- traceability.

## 8. Drill « phrase courte »

Transformer une phrase trop longue en trois phrases simples.

Exemple difficile :

> Because the platform, which has been developed for many years, contains several dependencies that are not completely documented and because the migration window is short, we think that a progressive approach should probably be better.

Version plus claire :

> The platform has many legacy dependencies. Some of them are not fully documented. Because the migration window is short, I recommend a phased approach.

## 9. Drill « because »

Compléter oralement :

- We chose this option because...
- We rejected the alternative because...
- We need a transition architecture because...
- We cannot decommission the legacy system yet because...
- We need a compliance review because...
- We should iterate on Phase C because...

## 10. Drill « trade-off »

Pour chaque paire, produire 30 secondes :

- speed vs risk
- standardization vs team autonomy
- short-term cost vs long-term maintainability
- reuse vs local optimization
- consistency vs flexibility
- availability vs complexity
- security vs usability

Formule :

> The trade-off is between X and Y. Option A improves X but creates Y. In this context, I would prioritize... because...

## 11. Drill « interviewer interrupts »

Commencer une réponse de deux minutes. Après 20 secondes, imaginer :

- `Can you be more specific?`
- `Why?`
- `What was your personal contribution?`
- `What was the risk?`
- `What was the result?`

Répondre directement, sans recommencer toute l’histoire.

## 12. Drill « recover from a mistake »

Phrases :

- `Sorry, let me correct that.`
- `I used the wrong term. I mean...`
- `Let me rephrase the point.`
- `More precisely...`

## 13. Self-evaluation

Après enregistrement, noter 0/1 :

- Ai-je donné le contexte ?
- Ai-je répondu à la question ?
- Ai-je expliqué pourquoi ?
- Ai-je utilisé des phrases courtes ?
- Ai-je évité de traduire mot à mot ?
- Ai-je terminé clairement ?

Score cible : 5/6 ou 6/6, même avec un accent français.
