# English for Architects — TOGAF & Enterprise Architecture

## Purpose

Ce bloc aide un architecte francophone à **comprendre, expliquer et défendre une architecture en anglais**, sans transformer le dépôt TOGAF en cours général d’anglais.

Objectifs pratiques :

- comprendre le vocabulaire d’architecture et TOGAF utilisé en réunion ;
- expliquer une architecture de façon simple et structurée ;
- présenter Baseline, Target, gaps, roadmap et migration ;
- parler de risk, security, governance et trade-offs ;
- répondre à des questions d’entretien ;
- améliorer speaking et listening avec des drills courts ;
- savoir présenter le cas MayaBank en anglais.

## Principe pédagogique

On privilégie des phrases **courtes, réutilisables et professionnelles**.

Une bonne réponse d’architecte n’a pas besoin d’un anglais littéraire. Elle doit être :

1. structurée ;
2. compréhensible ;
3. précise ;
4. capable d’expliquer un choix ;
5. capable d’exprimer un risque ou une incertitude.

## Structure de réponse recommandée

Pour beaucoup de questions d’entretien :

```text
Context
→ Problem
→ Decision
→ Trade-off
→ Outcome / Next step
```

Exemple :

> The current payment platform is fragmented and difficult to operate. The main issue is not only technology; it is also ownership and governance. We therefore defined a target architecture with standardized APIs, event-driven integration, stronger observability, and clear data ownership. We did not choose a big-bang migration. We introduced transition architectures and migration waves to control risk.

## Règle importante

Ne pas chercher à traduire mot à mot le français. Apprendre des **blocs de phrases** réutilisables.

Exemples :

- `The main issue is...`
- `The target architecture aims to...`
- `The key trade-off is...`
- `We considered three options...`
- `The main risk is...`
- `To mitigate this risk...`
- `This decision is aligned with...`
- `We introduced a transition architecture because...`

## Objectif oral

Être capable de parler pendant :

- 30 secondes sur son rôle ;
- 2 minutes sur une architecture ;
- 5 minutes sur une transformation ;
- 15 à 30 minutes dans un entretien technique.
