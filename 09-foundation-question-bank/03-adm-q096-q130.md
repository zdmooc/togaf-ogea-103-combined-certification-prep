# Introduction to the ADM — Questions 096 à 130

## Q096 — Phase D
Quel domaine est développé en Phase D ?
A. Business Architecture  B. Technology Architecture  C. Migration Planning  D. Architecture Change Management
**Réponse : B.** Phase D développe la Technology Architecture. A=B phase, C=F, D=H.
**Mapping : ADM — Phase D.**

## Q097 — Target Technology
La Target Technology Architecture décrit principalement :
A. Les plateformes et technologies nécessaires pour soutenir les architectures cible  B. Les seuls objectifs métier  C. Les work packages priorisés  D. Les exceptions approuvées
**Réponse : A.** D traduit les besoins en architecture technologique. B/C/D relèvent d'autres moments.
**Mapping : ADM — Phase D.**

## Q098 — Baseline Technology
Quel exemple relève de la Baseline Technology Architecture ?
A. Les plateformes actuelles, middleware, infrastructure et services techniques  B. Le futur operating model métier  C. La roadmap finale  D. Un concern du sponsor
**Réponse : A.** Baseline Technology décrit l'existant technique pertinent. B/C/D sont d'autres éléments.
**Mapping : ADM — Phase D.**

## Q099 — Technology gap
La cible exige une haute disponibilité que la plateforme actuelle ne fournit pas. Il s'agit principalement :
A. D'un gap technologique  B. D'une Phase A complète  C. D'un stakeholder  D. D'un deliverable
**Réponse : A.** L'écart entre capacité technique actuelle et cible est un Technology gap. B/C/D ne décrivent pas l'écart.
**Mapping : ADM — Phase D/Gap.**

## Q100 — D vs E
Quelle distinction est correcte ?
A. D définit la cible technologique ; E cherche comment transformer les gaps en solutions/work packages  B. D priorise le portefeuille ; E définit la Business Architecture  C. D=G  D. E=H
**Réponse : A.** D termine la définition de domaine ; E bascule vers la transformation. Les autres réponses mélangent les phases.
**Mapping : ADM — D vs E.**

## Q101 — Phase E
Phase E s'appelle :
A. Architecture Vision  B. Opportunities & Solutions  C. Migration Planning  D. Implementation Governance
**Réponse : B.** E = Opportunities & Solutions. C=F, D=G, A=A.
**Mapping : ADM — Phase E.**

## Q102 — But de E
Le but principal de Phase E est de :
A. Consolider les gaps et identifier les options de transformation, work packages et Transition Architectures  B. Définir la vision initiale  C. Contrôler le code en production  D. Réviser uniquement les principles
**Réponse : A.** E prépare la transformation à partir des architectures définies. B=A, C=G/delivery, D n'est pas son but principal.
**Mapping : ADM — Phase E.**

## Q103 — Work Packages
Dans l'ADM, les work packages deviennent particulièrement importants en :
A. Phase E  B. Preliminary uniquement  C. Phase A uniquement  D. Phase H uniquement
**Réponse : A.** E identifie et regroupe les changements en work packages. Ils pourront ensuite être priorisés en F.
**Mapping : ADM — Phase E.**

## Q104 — Transition Architecture
Pourquoi Phase E peut-elle définir des Transition Architectures ?
A. Pour décrire des états intermédiaires cohérents nécessaires entre Baseline et Target  B. Pour remplacer la Target  C. Pour supprimer la migration  D. Pour éviter la gouvernance
**Réponse : A.** Les transitions permettent une trajectoire réaliste. B/C/D sont faux.
**Mapping : ADM — Phase E/Transition Architecture.**

## Q105 — Big bang
Quel choix est le plus cohérent avec une transformation complexe ?
A. Chercher des Transition Architectures si un passage direct est trop risqué  B. Toujours imposer un big bang  C. Ignorer les dépendances  D. Déployer avant d'identifier les gaps
**Réponse : A.** Les transitions réduisent le risque et structurent la trajectoire. B/C/D sont anti-méthodiques.
**Mapping : ADM — Phase E.**

## Q106 — Candidate Roadmap
En Phase E, l'Architecture Roadmap est généralement :
A. Enrichie avec les work packages et transitions candidates  B. Supprimée  C. Remplacée par le code  D. Limitée aux incidents
**Réponse : A.** E transforme les gaps en éléments de trajectoire. B/C/D sont faux.
**Mapping : ADM — Phase E/Roadmap.**

## Q107 — E vs F
Quelle phrase est la plus juste ?
A. E identifie la transformation ; F la priorise et la séquence  B. E et F sont identiques  C. F définit la Technology Architecture  D. E gouverne l'implémentation
**Réponse : A.** C'est la distinction essentielle. C=D, D=G.
**Mapping : ADM — E vs F.**

## Q108 — Phase F
Phase F s'appelle :
A. Migration Planning  B. Business Architecture  C. Implementation Governance  D. Architecture Vision
**Réponse : A.** F = Migration Planning. Les autres sont B/G/A.
**Mapping : ADM — Phase F.**

## Q109 — Prioritization
En Phase F, on cherche notamment à :
A. Prioriser les work packages selon valeur, coût, risque et dépendances  B. Redéfinir tous les stakeholders  C. Choisir le scope initial  D. Construire uniquement des viewpoints
**Réponse : A.** F transforme la roadmap en plan de migration réaliste. B/C/D ne sont pas son objectif principal.
**Mapping : ADM — Phase F.**

## Q110 — Implementation and Migration Plan
Quel deliverable est particulièrement associé à Phase F ?
A. Implementation and Migration Plan  B. Request for Architecture Work  C. Architecture Vision uniquement  D. Governance Log uniquement
**Réponse : A.** F produit/affine le plan d'implémentation et migration. B est amont ; C=A ; D traverse la gouvernance.
**Mapping : ADM — Phase F.**

## Q111 — Migration waves
Pourquoi organiser des migration waves ?
A. Pour séquencer des ensembles de changements selon dépendances et capacité d'exécution  B. Pour éviter toute priorisation  C. Pour remplacer les work packages  D. Pour supprimer les Transition Architectures
**Réponse : A.** Les waves structurent l'exécution dans le temps. B/C/D sont faux.
**Mapping : ADM — Phase F.**

## Q112 — Business value assessment
Quelle information aide particulièrement la priorisation en F ?
A. Business value et risk  B. Couleur des diagrams  C. Nombre de pages  D. Préférence personnelle d'un développeur
**Réponse : A.** Valeur, coûts, risques et dépendances soutiennent la priorisation. B/C/D sont arbitraires.
**Mapping : ADM — Phase F.**

## Q113 — Dependency analysis
Pourquoi analyser les dépendances entre work packages ?
A. Pour éviter un séquencement irréaliste  B. Pour choisir un viewpoint  C. Pour remplacer Phase E  D. Pour réduire le nombre de stakeholders
**Réponse : A.** Une migration doit respecter les prérequis techniques, métier et organisationnels.
**Mapping : ADM — Phase F.**

## Q114 — Architecture Roadmap vs Migration Plan
Quelle distinction est correcte ?
A. La Roadmap exprime la trajectoire d'architecture ; le Migration Plan précise davantage l'exécution et le séquencement  B. Ils sont toujours identiques  C. La Roadmap est un contrat juridique  D. Le Migration Plan est une view de stakeholder
**Réponse : A.** Les deux sont liés mais pas synonymes. B/C/D sont faux.
**Mapping : ADM — Phase E/F.**

## Q115 — F vers G
Après qu'une migration a été planifiée et approuvée, quelle phase gouverne sa mise en œuvre ?
A. Phase G  B. Phase B  C. Preliminary  D. Phase C
**Réponse : A.** G = Implementation Governance.
**Mapping : ADM — F to G.**

## Q116 — Phase G
Phase G s'appelle :

## Q117 — But de G

## Q118 — Architecture Contract en G
En Phase G, un Architecture Contract aide principalement à :
A. Formaliser les engagements entre architecture et implementation  B. Remplacer les requirements  C. Choisir les stakeholders  D. Définir la Baseline Business

## Q119 — Compliance Review
Une Architecture Compliance Review sert à :

## Q120 — Deviation
Une équipe d'implémentation ne peut pas respecter une contrainte d'architecture. Quelle est la meilleure réaction ?

**Mapping : ADM — Phase G/Governance.**

## Q122 — Implementation evidence

## Q123 — Change request pendant G
