# Corrections — X2202 Foundation 7.3 : les 16 livrables

Chaque correction explique la distinction principale. Les questions ne proviennent pas d'un examen officiel.

## D01 — B : Request for Architecture Work

**Réponse : B.** La demande déclenche l'engagement ; elle n'est pas le mandat de l'architecte déjà négocié. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D02 — D : Statement of Architecture Work

**Réponse : D.** Le Statement décrit le travail architectural convenu ; il ne remplace ni la Vision ni les exigences détaillées. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D03 — A : Architecture Vision

**Réponse : A.** La Vision établit l'alignement initial ; les modèles détaillés et le plan d'exécution viennent ensuite. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D04 — C : Communications Plan

**Réponse : C.** Le Communications Plan organise les messages, destinataires, canaux et rythmes ; il ne définit pas les engagements d'implémentation. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D05 — B : Business Principles, Business Goals, and Business Drivers

**Réponse : B.** Ces fondements métier orientent le travail architectural ; ils ne sont pas encore les descriptions Baseline/Target. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D06 — D : Capability Assessment

**Réponse : D.** La Capability Assessment examine les capacités ; la Roadmap présente un itinéraire de transformation. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D07 — A : Architecture Principles

**Réponse : A.** Les principes guident les décisions transverses ; les requirements précisent les conditions à satisfaire. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D08 — C : Architecture Definition Document

**Réponse : C.** Le Definition Document décrit les architectures ; la Requirements Specification décrit ce qu'elles doivent satisfaire. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D09 — B : Architecture Requirements Specification

**Réponse : B.** La spécification consolide les exigences ; elle ne doit pas être confondue avec les diagrammes ni le planning. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D10 — D : Architecture Roadmap

**Réponse : D.** La Roadmap présente la trajectoire et les grands états ; le Migration Plan détaille les séquences d'exécution. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D11 — A : Implementation and Migration Plan

**Réponse : A.** Le plan de migration apporte le séquencement détaillé de mise en œuvre à partir des travaux préparés. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D12 — C : Implementation Governance Model

**Réponse : C.** Le Governance Model définit comment piloter et contrôler la réalisation, à distinguer des obligations contractuelles spécifiques. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D13 — B : Architecture Contract

**Réponse : B.** Le Contract formalise les engagements entre les parties ; le Governance Model décrit les règles du dispositif général. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D14 — D : Compliance Assessment

**Réponse : D.** L'Assessment mesure la conformité de la réalisation par rapport à la cible et aux exigences approuvées. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D15 — A : Change Request

**Réponse : A.** La Change Request est la demande de modification ; l'Impact Assessment en analyse les conséquences. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.

## D16 — C : Requirements Impact Assessment

**Réponse : C.** L'Impact Assessment examine les conséquences d'une requirement modifiée ; ce n'est pas la demande de changement elle-même. Les trois autres options désignent des livrables réels, mais avec d'autres rôles dans l'ADM.
