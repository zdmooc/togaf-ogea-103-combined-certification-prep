# Gouvernance de l’architecture

## Gouvernance ≠ simple gestion de projet

La gouvernance d’architecture sert à garantir que les décisions, trajectoires et réalisations restent cohérentes avec les objectifs et principes d’architecture.

## Elle sert à

- cadrer les décisions ;
- arbitrer les écarts ;
- vérifier la conformité ;
- gérer les exceptions ;
- tracer les choix ;
- protéger la cohérence de long terme.

## Éléments clés

### 1. Rôles et responsabilités
Qui décide ? Qui recommande ? Qui valide ? Qui exécute ?

### 2. Compliance
Une architecture utile ne reste pas théorique.
Elle doit être vérifiée dans la mise en œuvre.

### 3. Exceptions
Certaines dérogations sont parfois nécessaires.
Mais elles doivent être :
- justifiées ;
- limitées ;
- tracées ;
- temporisées si besoin.

### 4. Liens avec le delivery
La gouvernance ne doit pas être hors-sol.
Elle doit être connectée au delivery réel.

## Erreurs fréquentes

- gouvernance perçue comme simple blocage ;
- absence de cadre pour les exceptions ;
- pas de traçabilité des décisions ;
- pas de lien entre architecture cible et livraison concrète.

## Exemple terrain

### Demande de dérogation sécurité
Une équipe veut aller plus vite.
Le réflexe mature consiste à :
- évaluer le risque ;
- tracer la dérogation ;
- fixer une échéance ;
- prévoir la remédiation ;
- ne pas casser les principes sans contrôle.
