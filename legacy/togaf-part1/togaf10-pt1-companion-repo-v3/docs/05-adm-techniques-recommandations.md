# ADM — Techniques et recommandations

## Idée générale

TOGAF ne se limite pas à une séquence de phases.
Il propose aussi des techniques d’appui pour améliorer la qualité du travail d’architecture.

## 1. Business Scenarios

Les scénarios métier aident à rendre les besoins plus concrets.
Ils relient la théorie aux situations réelles.

Ils servent à :
- clarifier le problème ;
- identifier les acteurs ;
- préciser les attentes ;
- ancrer les exigences.

## 2. Gap Analysis

La gap analysis permet de comparer l’existant et la cible.

Elle aide à identifier :
- ce qui existe déjà ;
- ce qu’il faut faire évoluer ;
- ce qu’il faut retirer ;
- ce qu’il faut créer.

## 3. Risk Management

Une bonne architecture ne promet pas une cible abstraite parfaite.
Elle identifie aussi les risques :
- techniques ;
- organisationnels ;
- de gouvernance ;
- de sécurité ;
- de dépendances ;
- de planning.

## 4. Interoperability

Les systèmes vivent rarement seuls.
Il faut réfléchir à l’intégration, aux échanges, aux dépendances et aux standards.

## 5. Architecture Principles

Les principes servent à prendre de meilleures décisions dans le temps.
Ils sont utiles quand plusieurs options sont possibles.

## 6. Migration Planning support

La transformation passe souvent par des étapes.
Les techniques associées aident à prioriser et à séquencer.

## Recommandations pratiques

- toujours relier les techniques à un besoin concret ;
- ne pas produire un catalogue de techniques sans usage ;
- utiliser la bonne technique au bon moment ;
- garder une logique de parties prenantes et de décision.

## Exemple simple

### Cas : modernisation d’une plateforme ODM
- Business scenario : besoin de modernisation et de sécurité
- Gap analysis : VM actuelles vs plateforme cible
- Risk management : risques licence, sécurité, dépendances, exploitation
- Principles : standardisation, observabilité, sécurité par défaut
