# Appliquer l’ADM

## Pourquoi cette partie compte

Beaucoup de candidats savent réciter des notions, mais ont du mal à expliquer comment l’ADM est utilisé en vrai.

## Appliquer l’ADM, cela veut dire

- l’adapter au contexte ;
- choisir le bon niveau de détail ;
- tenir compte de la taille de l’organisation ;
- gérer les contraintes de sécurité, d’agilité, de calendrier et de gouvernance ;
- travailler par périmètres et itérations.

## 1. Adaptation

L’ADM n’est pas monolithique.
On l’adapte selon :
- la maturité de l’organisation ;
- le niveau de formalisme attendu ;
- le périmètre ;
- le type d’initiative ;
- la complexité.

## 2. Partitioning

On peut découper le travail d’architecture par :
- domaine ;
- entité ;
- programme ;
- niveau de détail ;
- capacité transverse.

## 3. Levels

Tous les sujets n’exigent pas le même niveau :
- stratégique ;
- macro ;
- solution ;
- domaine ;
- implémentation gouvernée.

## 4. Iteration

Une architecture utile progresse par itérations.
On ne comprend pas tout au premier passage.

## 5. Security / Governance / Agile

Appliquer l’ADM suppose aussi de tenir compte :
- de la sécurité ;
- de la conformité ;
- de l’agilité ;
- des dépendances delivery ;
- de la réalité organisationnelle.

## Point essentiel

Le bon architecte n’applique pas mécaniquement TOGAF.
Il sait **calibrer** la démarche.

## Cas concret

### Migration d’un portefeuille vers OpenShift
On peut :
- commencer par un lot pilote ;
- ajuster les principes ;
- faire plusieurs itérations ;
- gouverner les écarts ;
- enrichir progressivement la cible.
