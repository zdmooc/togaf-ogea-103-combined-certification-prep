# Introduction à l’ADM

## ADM = Architecture Development Method

L’ADM est le cœur opératoire de TOGAF.
Il donne une façon structurée de conduire un travail d’architecture.

## Ce qu’il ne faut pas faire

Ne pas l’apprendre comme une roue figée récitable sans sens.

## Ce qu’il faut comprendre

L’ADM sert à :

- cadrer ;
- faire émerger une vision ;
- définir les architectures ;
- préparer la transformation ;
- gouverner l’exécution ;
- gérer le changement.

## Logique générale

L’ADM progresse de manière structurée mais peut être :

- itératif ;
- adapté ;
- découpé ;
- réutilisé par domaine ;
- piloté par le contexte.

## Les grandes zones à connaître

### Preliminary
Préparer la capacité d’architecture et le cadre.

### Phase A
Construire la vision d’architecture.

### Phases B, C, D
Définir les architectures métier, systèmes d’information et technologique.

### Phases E, F
Préparer les opportunités, solutions et la migration.

### Phase G
Assurer la gouvernance de mise en œuvre.

### Phase H
Gérer le changement d’architecture.

### Requirements Management
Gérer les exigences tout au long du cycle.

## Ce qu’il faut savoir pour Part 1

Tu dois surtout savoir :
- le rôle des phases ;
- la logique de progression ;
- la place des exigences ;
- le fait que l’ADM s’adapte au contexte.

## Erreurs fréquentes

- croire que chaque phase doit être traitée au même niveau de détail ;
- oublier que les exigences traversent tout ;
- penser que la cible suffit sans roadmap.
