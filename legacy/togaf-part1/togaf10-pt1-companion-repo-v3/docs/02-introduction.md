# Introduction

## Pourquoi TOGAF peut sembler difficile au début

Les difficultés les plus fréquentes sont :

- beaucoup de vocabulaire ;
- beaucoup de concepts proches ;
- tendance à apprendre par cœur sans comprendre ;
- confusion entre architecture, projet, gouvernance et modélisation.

## Bonne posture de départ

Il faut voir TOGAF comme :

- un **cadre de travail** ;
- une **méthode d’architecture** ;
- un **langage de gouvernance** ;
- un **support de transformation**.

## Idée centrale

TOGAF aide à **aligner** :

- la stratégie ;
- les besoins métier ;
- les applications ;
- les technologies ;
- les décisions d’évolution.

## Ce qu’il faut retenir dès le départ

- l’architecture n’est pas qu’un dessin ;
- l’architecture n’est pas qu’un catalogue d’outils ;
- l’architecture n’est pas qu’un projet technique ;
- l’architecture cherche la cohérence et la trajectoire.

## Mini-checklist

À la fin de l’introduction, tu dois savoir expliquer :
- ce qu’est l’architecture d’entreprise ;
- pourquoi TOGAF est utilisé ;
- à quoi sert l’ADM ;
- pourquoi il faut gouverner l’architecture.
