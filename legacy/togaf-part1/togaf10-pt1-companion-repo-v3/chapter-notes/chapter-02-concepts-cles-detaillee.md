# Chapitre 2 — Concepts clés détaillés

## Objectif du chapitre
Maîtriser les termes fondamentaux qui servent de socle à tout le reste.

## Concepts à ancrer
- Enterprise Architecture
- stakeholder
- concern
- requirement
- constraint
- principle
- baseline architecture
- target architecture
- transition architecture
- value of architecture

## Méthode d’apprentissage
Pour chaque notion :
1. définition simple
2. différence avec notions proches
3. exemple terrain
4. piège classique

## Exemple
### Principle
Règle stable qui guide les décisions.
Exemple : “observabilité par défaut”.

### Requirement
Besoin à satisfaire.
Exemple : “la solution doit tracer les accès utilisateurs”.

### Constraint
Limite imposée.
Exemple : “hébergement on-prem obligatoire”.

## Piège majeur
Confondre besoin, règle de décision et contrainte.

## Auto-test
Explique la différence entre :
- principle et requirement
- baseline et target
- target et transition
