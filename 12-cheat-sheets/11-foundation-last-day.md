# Cheat Sheet — Foundation Last Day

## Objectif

La veille de l’examen Foundation, ne pas essayer de relire tout le standard. Réviser les **distinctions à fort rendement** et vérifier qu’aucune zone officielle n’est laissée vide.

## Format à retenir

- 40 questions
- 60 minutes
- multiple choice
- closed book
- réussite à 60 %

Répartition officielle :

- Concepts — 8
- Introduction to the ADM — 14
- ADM Techniques — 6
- Applying the ADM — 4
- Architecture Governance — 3
- Architecture Content — 5

## Les 15 distinctions prioritaires

1. Preliminary vs Phase A
2. Phase A vs Phase B
3. Data vs Application Architecture
4. Phase D vs Phase E
5. Phase E vs Phase F
6. Phase F vs Phase G
7. Phase G vs Phase H
8. H vs Requirements Management
9. Baseline vs Target vs Transition
10. Deliverable vs Artifact vs Building Block
11. ABB vs SBB
12. View vs Viewpoint
13. Repository vs Enterprise Continuum
14. Architecture Roadmap vs Implementation & Migration Plan
15. Architecture Governance vs Project Governance

## L’ADM en 30 secondes

```text
Preliminary = capability
A = vision/scope/stakeholders
B = business
C = data + application
D = technology
E = opportunities, work packages, transitions
F = prioritize and sequence migration
G = govern implementation
H = manage architecture change
Requirements = transversal
```

## Architecture Content

Mémoriser :

```text
Deliverable → contains Artifacts → represent Building Blocks
```

Artifacts : Catalog / Matrix / Diagram.

## Techniques

- stakeholders → Stakeholder Management
- besoin métier → Business Scenario
- Baseline vs Target → Gap Analysis
- capacité à fonctionner ensemble → Interoperability
- capacité de l’organisation à changer → Readiness
- incertitude/impact → Risk Management
- capacités stratégiques → Capability-Based Planning
- ordre de migration → Migration Planning Techniques

## Gouvernance

- Board = arbitrage
- Contract = engagements
- Compliance Review = conformité
- deviation = écart
- exception = écart gouverné/autorisé

## Stratégie de temps

60 min / 40 questions = environ **90 secondes par question** en moyenne.

Méthode :

1. répondre vite aux définitions sûres ;
2. marquer mentalement les confusions ;
3. éliminer les options manifestement hors concept ;
4. ne pas surinterpréter un QCM Foundation comme un scénario Practitioner.

## Les erreurs à éviter

- choisir la réponse la plus technique au lieu du concept TOGAF exact ;
- confondre plan et architecture ;
- supposer que TOGAF impose un waterfall rigide ;
- traiter security/risk comme sujets tardifs ;
- confondre artifact et deliverable ;
- oublier que Requirements Management est transversal.

## Test oral final

Être capable d’expliquer sans notes :

- les 10 étapes Preliminary→H ;
- les 4 domaines ;
- E vs F ;
- G vs H ;
- Deliverable/Artifact/Building Block ;
- View/Viewpoint ;
- Repository/Continuum.

Si une explication dépasse 30 secondes, la simplifier.

## English minimum

> Preliminary establishes the architecture capability. Phase A establishes the vision and scope. B, C, and D develop the target architectures. E and F organize migration. G governs implementation. H manages architectural change.
