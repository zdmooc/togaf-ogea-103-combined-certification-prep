## Présenter TOGAF en 30 secondes

> TOGAF is an enterprise architecture framework centered on the Architecture Development Method. It helps structure architecture work from business drivers and stakeholders through target architectures, migration planning, implementation governance, and change management.

## Expliquer l’ADM

> Preliminary establishes the architecture capability. Phase A defines the vision, scope, stakeholders, and value. Phases B, C, and D develop the Business, Data, Application, and Technology Architectures. Phases E and F organize the transformation and migration. Phase G governs implementation. Phase H manages architectural change. Requirements Management supports the whole cycle.

## Expliquer E vs F

> Phase E identifies solution options, work packages, and transition architectures. Phase F prioritizes and sequences those work packages into an implementation and migration plan.

## Expliquer G vs H

> Phase G checks that implementation remains compliant with the approved architecture. Phase H evaluates significant change and decides how the architecture should evolve.

## Expliquer Stakeholder Management

> I identify the key stakeholders, understand their concerns, select the appropriate viewpoints, and produce the views needed to support architecture decisions.

## Expliquer Baseline / Target / Gap

> The Baseline describes the current state. The Target describes the desired future state. Gap Analysis identifies what must change between the two.

## Expliquer une migration

> I avoid a big-bang migration when the risk is high. I define work packages, transition architectures, dependencies, and migration waves so that the organization can move toward the target incrementally.

## Expliquer la gouvernance

> Architecture governance makes decisions, compliance checks, deviations, and exceptions explicit and traceable. The Architecture Board provides governance and arbitration, while compliance reviews check implementation against the approved architecture.

## Répondre à « Tell me about an architecture project »

Structure simple :

1. Context
2. Problem
3. Stakeholders
4. Architecture approach
5. Key decisions
6. Migration
7. Governance
8. Result

Exemple :

> I worked on a payment platform modernization. The main challenge was to improve resilience and delivery speed without creating migration risk. I clarified the stakeholders and requirements, developed the target architecture across business, data, application, and technology domains, identified the major gaps, and organized the transformation into work packages and migration waves. I also defined governance and compliance checkpoints to keep delivery aligned with the architecture.

## Phrases de secours

Quand un mot manque :

> Let me explain it in a simpler way.

> The main point is that…

> From an architecture perspective…

> The key trade-off was between…

> We decided to… because…

> The main risk was…

> The target state was…

> The migration was organized in several steps.

## Erreurs à éviter

- phrases trop longues ;
- traduire mot à mot le français ;
- chercher un vocabulaire compliqué ;
- utiliser « actually » pour dire « actuellement » ;
- utiliser des termes techniques sans expliquer le pourquoi.

## Règle finale

La priorité n’est pas l’accent parfait. La priorité est : **correct concept + clear structure + short sentence + confident delivery**.
