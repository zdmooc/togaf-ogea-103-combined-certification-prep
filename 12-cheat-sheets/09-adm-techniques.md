# Cheat Sheet — ADM Techniques

## Quel problème → quelle technique ?

| Problème | Technique à penser |
|---|---|
| Qui compte et que veulent-ils ? | Stakeholder Management |
| Quel besoin métier concret devons-nous traduire ? | Business Scenarios |
| Qu’est-ce qui change entre Baseline et Target ? | Gap Analysis |
| Les composants/organisations peuvent-ils fonctionner ensemble ? | Interoperability Analysis |
| L’organisation est-elle prête pour la transformation ? | Business Transformation Readiness |
| Qu’est-ce qui peut mal tourner ? | Risk Management |
| Quelles capacités devons-nous développer ? | Capability-Based Planning |
| Comment comparer/prioriser la migration ? | Migration Planning Techniques |

## Stakeholder Management

Chaîne :

```text
Stakeholder → Concern → Viewpoint → View → Requirement / Decision
```

Piège : stakeholder ≠ sponsor uniquement.

## Business Scenarios

Objectif : transformer un problème/opportunité métier en exigences exploitables.

Chaîne :

```text
Problem / Opportunity → Actors → Environment → Desired Outcome → Requirements
```

## Gap Analysis

```text
Baseline → compare → Target → Gaps
```

Le gap décrit **ce qui manque/change**, pas le planning pour le réaliser.

## Interoperability

Regarder plusieurs dimensions :

- business ;
- data/information ;
- application ;
- technology ;
- governance/organization selon le contexte.

## Business Transformation Readiness

Question : l’entreprise peut-elle réellement absorber le changement ?

Regarder : sponsorship, skills, culture, funding, governance, delivery capacity, dependencies.

## Risk Management

Chaîne simple :

```text
Identify → Assess → Treat/Mitigate → Monitor
```

Security et risk sont transverses, pas ajoutés uniquement en Phase G.

## Capability-Based Planning

Partir de ce que l’entreprise doit être capable de faire, puis connecter initiatives, architectures et investissements.

Piège : capability ≠ application.

## Migration Planning Techniques

Utilisées surtout pour éclairer Phase F : value, risk, cost, dependencies, readiness, benefits et contraintes.

## Réflexe Practitioner

Si plusieurs réponses semblent correctes, choisir celle qui :

1. utilise la technique adaptée au problème ;
2. arrive au bon moment ADM ;
3. conserve requirements et stakeholders ;
4. évite une solution prématurée.

## English

> I select architecture techniques based on the problem to solve: stakeholders, gaps, readiness, risk, capabilities, interoperability, or migration priorities.
