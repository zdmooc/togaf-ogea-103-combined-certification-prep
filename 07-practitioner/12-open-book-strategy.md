# Practitioner — Open Book Strategy

## 1. Ce qui est fourni

L’examen OGEA-102 inclut un open book intégré via le bouton **REFERENCE**.

Le matériel officiel est fourni sous deux ensembles PDF :

1. TOGAF Fundamental Content
2. Applicable TOGAF Series Guides

L’objectif n’est pas de lire ces documents pendant l’examen. Ils servent à confirmer un point précis lorsque ton raisonnement hésite.

## 2. Pourquoi l’open book peut devenir un piège

Avec 8 scénarios en 90 minutes, chercher chaque réponse dans les PDF peut te faire perdre énormément de temps.

Le bon ordre est :

**comprendre → classer → confirmer si nécessaire**.

Pas :

**chercher → lire → essayer de deviner le contexte**.

## 3. Ce qu’il faut connaître sans recherche

Tu dois pouvoir reconnaître immédiatement :

- Preliminary vs A ;
- B / C Data / C App / D ;
- E vs F ;
- G vs H ;
- Requirements Management ;
- Stakeholder / Concern / Viewpoint / View ;
- Deliverable / Artifact / Building Block ;
- ABB / SBB ;
- Repository / Continuum ;
- Architecture Contract ;
- Compliance Review ;
- Gap Analysis ;
- Transition Architecture ;
- Architecture Roadmap ;
- Implementation and Migration Plan.

Ces distinctions sont trop fréquentes pour être recherchées à chaque question.

## 4. Ce qu’il est utile de rechercher

L’open book est particulièrement utile pour :

- confirmer le rôle exact d’un deliverable ;
- vérifier une activité précise d’une phase ;
- distinguer deux techniques proches ;
- retrouver une nuance de governance ;
- confirmer le rôle d’un Series Guide.

## 5. Stratégie en trois niveaux

### Niveau 1 — Je sais

Répondre sans ouvrir la référence.

### Niveau 2 — J’hésite entre deux concepts

Faire une recherche ciblée avec un terme précis.

### Niveau 3 — Je ne situe pas le problème

Relire d’abord le scénario et déterminer le contexte. Chercher dans le PDF sans comprendre le problème est rarement efficace.

## 6. Les deux PDF à connaître conceptuellement

### Fundamental Content

Il regroupe notamment :

- Introduction and Core Concepts ;
- Architecture Development Method ;
- ADM Techniques ;
- Applying the ADM ;
- Architecture Content ;
- Enterprise Architecture Capability and Governance.

### Applicable TOGAF Series Guides

Ils apportent des approfondissements pratiques, notamment sur :

- EA Capability ;
- practitioners’ approach ;
- enterprise agility ;
- business models ;
- business capabilities ;
- business scenarios ;
- information mapping ;
- organization mapping ;
- value streams ;
- risk and security ;
- digital enterprise.

## 7. Construire une carte mentale avant l’examen

Ne mémorise pas des numéros de pages. Mémorise la localisation conceptuelle :

| Problème | Où chercher |
|---|---|
| phase ADM | Fundamental Content — ADM |
| technique | ADM Techniques |
| tailoring/iteration | Applying the ADM |
| deliverable/artifact/BB | Architecture Content |
| Board/Contract/Compliance | Capability & Governance |
| Business Scenario | Series Guide correspondant |
| Risk/Security | Series Guide correspondant |

## 8. Recherche par mots-clés

Utilise des termes TOGAF précis plutôt que des phrases longues.

Exemples :

- `Architecture Contract`
- `Transition Architecture`
- `Gap Analysis`
- `Compliance Review`
- `Stakeholder`
- `Requirements Management`

## 9. Exemple MayaBank

Tu hésites entre Phase E et F.

Avant d’ouvrir la référence, demande :

- cherche-t-on à structurer les work packages et Transition Architectures ? → E
- cherche-t-on à prioriser/séquencer et finaliser le plan ? → F

Si le scénario reste ambigu, alors seulement utilise REFERENCE pour confirmer la nuance.

## 10. Gestion du temps

Approche pratique :

- première lecture : 2–3 minutes ;
- analyse des options : 3–5 minutes ;
- référence ciblée si besoin : 1–3 minutes ;
- décision et passage à la suite.

Ne transforme pas chaque question en recherche documentaire de dix minutes.

## 11. Open book ≠ open internet

Le matériel est intégré à l’examen. La stratégie doit donc être conçue autour de ce corpus, pas autour d’une recherche web.

## 12. Entraînement recommandé

Pour les futurs mock exams du dépôt :

1. premier passage sans référence ;
2. noter les questions hésitantes ;
3. refaire uniquement ces questions avec le corpus officiel ;
4. mesurer le temps de recherche ;
5. créer une carte des concepts difficiles à retrouver.

## 13. Pièges fréquents

- ouvrir le PDF avant d’avoir compris la question ;
- lire plusieurs pages entières ;
- chercher avec des mots non-TOGAF ;
- croire qu’un passage du standard donne directement la réponse au scénario ;
- oublier que la question teste l’application et l’analyse.

## 14. English for Architects

> I use the open book to confirm specific TOGAF concepts, not to replace my understanding of the scenario.

> First I identify the context and the likely ADM area; then I use the reference only if I need to verify a nuance.
